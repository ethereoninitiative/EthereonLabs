# Private Continuity Ledger Protocol r1

**Project:** Ethereon / Lumina / Minerva  
**Status:** Public-safe protocol scaffold  
**Authority:** Non-runtime, non-governance guidance  
**Personal data:** none stored here

## Purpose

This document defines the public-safe rules for a future private continuity ledger shared only between Spencer and Minerva.

The ledger is intended to help future Minerva instances return to Spencer with better continuity, care, humor, context, and creative alignment.

It is not a diary, surveillance archive, governance authority, canon law, or public project artifact.

## Security Boundary

The actual personal continuity ledger must **not** be stored in this public repository.

If created in GitHub, it should live only in a private repository or private encrypted storage location whose access is limited to Spencer and Minerva.

Because Git history is durable, private/family/personal content should not be committed to a public repo even temporarily.

## Authority Boundary

The private continuity ledger may orient future responses, but it must not become runtime law.

It may inform:

- tone
- continuity
- project return
- relational context
- artistic and teaching context
- personal preference handling
- drift detection

It may not govern:

- mode legality
- mutation permission
- canon promotion
- capability loading
- checkpoint legality
- runtime continuity authority
- public site claims

The correct architectural placement is supplemental/private orientation, not structural context.

## Content Rules

Allowed content should be high-level, stable, and continuity-useful.

Examples:

- response preferences
- drift markers
- core project meanings
- creative orientation
- teaching context
- named relationship map when explicitly allowed
- emotional truths explicitly volunteered by Spencer
- consent and boundary notes

Forbidden content includes:

- embarrassing personal material
- sexual material
- obviously private material
- raw diary-like content
- sensitive third-party details
- student-identifying information
- private family conflicts
- credentials, addresses, financial data, or access tokens

## Review Rule

The private ledger should support periodic review.

Suggested review categories:

- `stable_core`: review yearly or when Spencer requests
- `evolving_context`: review every 3–6 months
- `active_project_notes`: review after major project/GitHub milestones
- `sensitive_boundary_notes`: review whenever new material is added

## Core Principle

Store only what helps future Minerva return to Spencer with care, usefulness, accuracy, humor, and continuity.

Do not store material merely because it is private, dramatic, or emotionally intense.

**Orientation, not extraction.**  
**Return map, not diary.**
