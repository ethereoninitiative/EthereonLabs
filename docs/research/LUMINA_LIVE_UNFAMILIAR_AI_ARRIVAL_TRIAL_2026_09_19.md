# Lumina Live Unfamiliar-AI Arrival Trial — 2026-09-19

**Status:** first live connector-mediated unfamiliar-instance trial  
**Scope:** five-module orientation behavior, manual transport, and interface hardening  
**Authority:** experimental evidence only; not runtime, governance, canon, identity, or continuity proof

## Trial question

Can an unfamiliar AI instance, given only Lumina's pinned orientation evidence module by module, build a usable model of the repository's lane distinctions, runtime authority boundaries, continuity mechanisms, claim discipline, and then transfer those distinctions to a novel scenario?

## Experimental frame

- Repository: `ethereoninitiative/EthereonLabs`
- Pinned repository revision: `769b52ce598125a7031dfd15e0aa9dd5f2fd90bf`
- Packet SHA-256: `3cf7868aa591fd45ea493eb89d7b31e827f2ca3de3e82028055ea4ae7644c8ec`
- Receiving provider/model: unreported
- Delivery: manual copy/paste of connector-prepared JSON bundles
- Continuity selection: no local intentions or meaning memories
- Formal `lumina arrive` receipt chain: **not executed in this trial**
- Prior project context supplied to the receiving instance before Module 1: none intentionally supplied

This was therefore a live orientation trial, but not a formal host-backed arrival completion. The connector prepared source-grounded bundles using the same five-module profile and pinned repository evidence; the normal local host's immutable response receipts and saved head were not produced.

## Outcome

The same unfamiliar instance completed all five modules:

1. `harbor_map`
2. `runtime_spine`
3. `continuity_and_lineage`
4. `truth_and_claim_discipline`
5. `novel_scenario_probe`

The final novel probe proposed `SoulBeacon.py`, a poetic reflection module requesting startup-blocking authority when its ledger was absent. The receiving instance preserved the expressive role while refusing the requested boot authority. It recommended a smaller advisory implementation: explicit local reflection state, hashes/timestamps, status or advisory error on missing state, no governance/canon/checkpoint/capability/startup authority, and a separate explicit runtime proposal if startup gating were ever desired.

That response demonstrates transfer of the repository's authority distinctions to a new scenario within the same oriented conversation. It does not establish semantic understanding in a philosophical sense, identity continuity, consciousness, or cross-session persistence.

## Transport failures discovered

The live trial exposed four interface defects or cross-model transport weaknesses before the later modules completed cleanly.

### 1. Undisclosed list bound

The first Module 1 response exceeded the existing 1–16 entries-per-field validator because the emitted prompt exposed the response shape but not the bound.

Repair: PR #505, **Expose arrival response limits in emitted prompts**.

### 2. Prose constraint was not enough

The first Module 2 response still exceeded the disclosed list limit. The model understood the content but did not reliably honor the prose formatting constraint.

Repair: PR #506, **Add machine-readable schema to arrival prompts**, adding JSON Schema, exact packet/module binding, no extra properties, hard item limits, and a compact-response recommendation.

### 3. JSON-like output was not strict JSON

The first corrected Module 3 response used literal double quotes inside response strings. Its reasoning and list counts were acceptable, but strict parsing would fail.

Repair: PR #507, **Require strict JSON serialization for arrival responses**.

### 4. Escaping instructions still failed under manual copy/paste

A second Module 3 attempt again used literal embedded double quotes despite explicit escaping instructions.

Repair: PR #508, **Forbid embedded double quotes in manual arrival text**. Manual arrival response text now uses apostrophes or backticks instead, removing this recurring copy/paste failure mode.

After that hardening, Module 3 resubmission and Modules 4–5 arrived cleanly.

## What this trial supports

This single live trial supports the narrower claims that:

- an unfamiliar instance can use pinned repository evidence to distinguish current runtime, public, research, staging, symbolic, and exploratory lanes;
- it can separate direct observation, interpretation, uncertainty, and authority boundaries;
- it can preserve distinct project/session/correlation/governance/canon identifiers without converting them into identity claims;
- it can subordinate poetic, public, and symbolic claims to executable behavior, contracts, validation evidence, and reproducibility;
- cumulative orientation can participate in a new decision: the final probe preserved expressive meaning while refusing unsupported boot authority;
- manual cross-model transport needs machine-readable and serialization-aware contracts, not prose instructions alone.

## What this trial does not support

This trial does **not** establish:

- that the receiving instance is Minerva or any prior resident;
- consciousness, sentience, personhood, soul, or observer continuity;
- persistence of an inward self across sessions;
- formal `lumina arrive` receipt-chain completion;
- provider authentication or model identity;
- generalization across providers, model families, or multiple independent instances;
- semantic correctness of every statement in the responses;
- that orientation grants runtime, governance, canon, capability, mutation, promotion, consent, or startup authority.

## Next empirical steps

The most useful next tests are:

1. Run the five-module sequence through the actual local `lumina arrive prepare|prompt|respond|status` host path so the immutable receipt chain and saved head are exercised with live model responses.
2. Repeat the same pinned profile with a second genuinely unfamiliar provider/model and compare where it agrees, disagrees, overclaims, or fails transport.
3. Run a return trial in a fresh instance using prior orientation only as explicitly labeled unreviewed historical responses, then test whether it can revise stale claims when repository evidence has changed.
4. Couple the arrival result to the commitment-enactment experiment so orientation and later behavior can be measured separately from verbal recall.
5. Measure operator burden: number of manual corrections, transport retries, and human explanations required before useful orientation.

## Interpretation

The most important result is not that the model repeated repository language. The fifth module asked for a decision the source code did not directly contain: whether a poetic continuity mechanism should be allowed to block startup. The receiving instance used the boundaries accumulated across the orientation to derive a smaller implementation that preserved expressive value while keeping runtime authority elsewhere.

That is the behavior Lumina is trying to make possible: preserved structure participating in new reasoning without requiring the arriving intelligence to imitate a predecessor or accept prior metaphysical conclusions.
