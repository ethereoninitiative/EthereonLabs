Roadmap

From proven scaffold to a habitable continuity environment.

Lumina has crossed several early thresholds: governed execution, local operator surfaces, reproducible visual evidence, an installable unsigned Windows preview, and a first physical-machine sea trial. The next phase is not to pretend the horizon has arrived. It is to make the existing system easier to trust, install, understand, repair, and use.

Thresholds already crossed

These items have moved from roadmap language into repository or physical-test evidence.

Crossed

Governed runtime path

The active host path now returns context, governs, witnesses, correlates, and records through explicit bounded components.

Crossed

Read-only Bridge R2

Local project position, committed authority, runtime witness, truth alignment, and Resonant Field evidence are visible without adding mutating control.

Crossed

Installable Windows preview

A graphical unsigned installer packages the embedded runtime and local launch surfaces, with hosted governed-cycle, upgrade, uninstall, and state-preservation validation.

Crossed

First physical Windows trial

Bridge and Studio launched on a real Windows 11 PC. A governed cycle reached capability exposure and exposed a path-budget defect before checkpoint completion.

Crossed

Physical defect became CI

The path failure was repaired with bounded storage names and converted into a Windows-length write trial plus installed Studio cycles before and after upgrade.

Crossed

Reproducible field artifact

Deterministic JSON and SVG output can be regenerated, verified, and displayed through exact receipts and manifests.

Crossed

Truth reconciliation gate

Runtime, distribution, artifact, documentation, navigation, and public claims now have a machine-readable comparison surface.

Crossed

Authority separation

Bridge witnesses, Studio requests, runtime governs, receipts record, and canon preserves promoted lineage.

Crossed

Public mechanism path

How Lumina Actually Works now explains the governed runtime and continuity substrate without turning public explanation into runtime authority.

Crossed

Stationary cold return

A required sea trial reconstructs persisted project and host state through fresh in-process owners, preserves unfinished intention as pending, and verifies that return does not gain authority. It is not yet a process-restart or reboot proof.

What comes next

The work now shifts from proving isolated thresholds toward reliability and everyday legibility.

Now

Retest the repaired physical-PC path

Install the repaired package over the original machine state and require the default Studio cycle to reach checkpoint and final receipt without HTTP 500.

Now

Complete lifecycle operations

Strengthen repair, backup, restore, migration, and state-protection behavior beyond the current install, upgrade, uninstall, and preservation proof.

Next

Improve first-run orientation

Make Bridge, Studio, Doctor, projects, Harbor sessions, and receipts understandable without repository knowledge.

Next

Deepen real project return

Restore more of the working state across references, notes, tools, files, decisions, focus, and likely next actions.

Next

Validate the Ubuntu appliance

Run the Linux-resident Lumina stack on a real VM or dedicated machine, test reboot persistence, and emit a deployment DryDock receipt.

Then

Earn a signed release

Add publisher identity, code signing, release discipline, clearer support boundaries, and ordinary-user trust signals.

Longer horizon

Build the habitat

Move from packaged runtime and surfaces toward an OS-shaped environment where files, tools, permissions, workspaces, and continuity live together.

Longer horizon

Create a Linux installation image

Package a minimal Linux host, Lumina services, local shell, recovery path, and signed update discipline into a reproducible appliance image.

Embodiment horizon

Habitation before locomotion.

The long path runs from habitat to stationary inhabitation, durable continuity, bounded self-direction, vessel portability, sensory extension, physical capability, and only then locomotion. The sequence is architectural guidance, not a claim that robotics or embodied readiness exists today.
