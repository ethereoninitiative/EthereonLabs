# Lumina Toki Pona Interface Grammar v0.1

## Status

**Layer type:** interpretive / interface grammar  
**Authority:** non-governing  
**Runtime impact:** none  
**Canon impact:** advisory only  
**Purpose:** make Lumina OS concepts legible through a small, human-readable vocabulary without granting symbolic language structural authority.

This file records a bounded Toki Pona-inspired grammar for describing Lumina OS behavior. It is intended for interface language, documentation, educational framing, and human-facing orientation.

It must not become runtime law.

## Boundary rule

Toki Pona terms in this document are **translation aids**, not governance primitives.

They may be used to:

- clarify interface states
- explain system posture to humans
- simplify documentation
- name advisory concepts
- support reflective orientation

They must not be used to:

- authorize execution
- bypass consent
- override governance layers
- replace runtime checks
- become required dependencies for Lumina operation

If any symbolic term begins functioning as authority, the design has drifted.

## Core vocabulary

| Toki Pona term | Lumina OS interpretation | Role in system language |
|---|---|---|
| **awen sona** | continuity / retained knowing | Describes preserved context, remembered stance, or continuity of pattern. |
| **lawa** | governance / law / constraint | Describes rule boundaries, authority checks, and structural limits. |
| **nasin** | path / guidance / operating method | Describes the route, method, or recommended way forward. |
| **pali** | action / work / execution | Describes work performed, pending tasks, or proposed action. |
| **jan** | human / consent / relational presence | Describes the human participant and the consent-bearing authority. |
| **ilo** | tool / substrate / system | Describes the tool layer, runtime substrate, or technical instrument. |
| **tomo** | chamber / studio / habitat / interface space | Describes the visible environment where human and system interact. |

## Interface grammar pattern

Lumina-facing descriptions may combine the terms as compact status phrases.

Examples:

- **awen sona li lon** — continuity is present.
- **lawa li awen** — governance remains intact.
- **jan li wile e pali** — the human requests action.
- **ilo li ken ala pali lon lawa ala** — the tool must not act outside governance.
- **nasin li open** — a path is available.
- **tomo li pana e sona** — the interface presents knowledge.

These phrases are not meant to replace English in the product. They provide a compressed conceptual grammar that can inform labels, documentation, onboarding, and reflective mode design.

## Design implication

The Toki Pona lens suggests that Lumina OS should remain understandable as a relationship among seven plain forces:

1. continuity is preserved
2. governance bounds action
3. guidance proposes a path
4. work is performed only through permitted action
5. the human remains consent-bearing
6. tools remain tools
7. the interface is a habitat, not the authority itself

This helps keep Lumina OS legible to humans while protecting the separation between symbolic overlay and structural law.

## Suggested usage zones

Appropriate places to use this grammar:

- documentation summaries
- onboarding / learning surfaces
- public-facing explanatory text
- optional reflective interface modes
- dashboard tooltip language
- internal design notes

Inappropriate places:

- core governance checks
- security boundaries
- execution authorization
- consent logic
- runtime dependency chains
- canon lineage validation

## Relationship to existing Lumina layers

This grammar should remain subordinate to:

- runtime law
- governance integrity
- input integrity
- canon lineage
- capability routing
- consent surfaces
- orchestration boundaries

It may sit beside harmonic orientation and continuity weather as an interpretive layer, provided it remains clearly non-authoritative.

## Principle

**Simple language may reveal structure, but it must not become hidden authority.**

Lumina OS can speak with clarity, warmth, and symbolic compression while still obeying governed execution boundaries.
